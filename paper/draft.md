# AdaColRAG: Query-Adaptive Visual Token Selection with Confidence-Aware Recovery for Efficient Document Retrieval

## Abstract

Visual document retrievers preserve layout, tables, charts, and figures by encoding rendered pages directly. Multi-vector retrievers such as ColPali retain fine-grained page evidence through token-level late interaction, but exhaustive scoring scales with both corpus size and the number of visual tokens per page. We propose **AdaColRAG**, a training-free retrieval framework that converts visual-token use into a query-time decision. A dense retriever first produces a candidate set; a query-complexity controller allocates a visual-token budget; a relevance--diversity--coverage selector removes redundant evidence; and a confidence estimator invokes full-token recovery only for uncertain queries. Unlike query-independent index compression, AdaColRAG retains the complete offline index and changes only the online scoring policy. An archived pilot on ViDoRe V3 Finance EN reached 0.4827 nDCG@5, compared with 0.4374 for exhaustive ColPali and 0.4744 for VisRAG-Ret, while reducing retrieval-stage CPU latency by 92.90% and full-corpus visual-token scoring work by 98.31%. That pilot used an adapter checkpoint that emitted a projection-layer loading warning and lacked identical-candidate controls. The submission protocol therefore reruns all encodings with the official merged ColPali checkpoint, evaluates 17 controlled systems on three English domains and one French domain, records repeated timing, and reports paired query-level bootstrap intervals. This design separates the effects of dense candidate generation, token budgeting, diversity-aware selection, score fusion, and confidence-aware recovery.

**Keywords:** visual document retrieval; multimodal retrieval; late interaction; visual-token selection; selective computation; retrieval-augmented generation

## 1 Introduction

Enterprise search increasingly operates over reports, presentations, invoices, forms, and scientific documents whose relevant evidence is not fully represented by plain text. Table structure, chart geometry, typography, and spatial associations can determine whether a page answers a query. OCR-first pipelines can discard these signals or propagate parsing errors. Visual document retrieval instead treats the rendered page as the primary retrieval unit [1--10].

ColPali [1] adapts ColBERT-style late interaction [11, 12] to page images. A page is represented by many visual embeddings, and every query token retrieves its strongest matching page token. This mechanism preserves local evidence but makes full-corpus scoring expensive. A page encoded at 448-pixel resolution contains 1,024 visual tokens; an exhaustive search over thousands of pages therefore performs millions of visual-token comparisons for every query.

The central observation of this work is that **the amount and location of necessary page evidence depend on the query**. A local value lookup can be answered from a small region, whereas an ambiguous or compositional request may require multiple distant regions. Query-independent patch removal cannot anticipate this distinction. Storage-oriented work such as Light-ColPali [5] compresses an index before the query is known. AdaColRAG studies the complementary online setting: it keeps the full index, retrieves a small candidate set, and chooses only the tokens required by the current query.

AdaColRAG combines four mechanisms. First, VisRAG-Ret [2] supplies dense candidate generation. Second, a budget controller estimates query complexity from query length, token dispersion, and coarse-ranking ambiguity. Third, a maximal-marginal-relevance-style selector [18] balances query relevance, redundancy suppression, and approximate page coverage. Fourth, a selective-prediction policy [19] reruns a larger candidate set with full tokens when the compressed ranking is uncertain.

Our contributions are:

1. **Query-time visual-token allocation.** We formulate page-token use as a query-conditioned retrieval decision rather than a permanent index transformation.
2. **Relevance--diversity--coverage selection.** We introduce a training-free selector for visual late interaction that preserves query evidence while suppressing redundant tokens.
3. **Confidence-aware recovery.** We estimate when compressed evidence is unreliable and selectively restore full-token scoring.
4. **Controlled efficiency attribution.** We introduce identical-candidate baselines that separately measure dense candidate generation, fixed and adaptive budgets, diversity-aware selection, fallback, and dense-score fusion.
5. **A submission-grade evaluation protocol.** The framework verifies checkpoint provenance, preserves query-level traces, evaluates four ViDoRe V3 domains, computes paired bootstrap intervals, records hardware and threading, and repeats key timing measurements.

## 2 Related Work

### 2.1 Visual document retrieval

Document Screenshot Embedding [4] represents rendered pages with a single vector, whereas ColPali [1] uses multi-vector late interaction to preserve fine-grained evidence. VisRAG [2] integrates direct visual retrieval into multimodal RAG. UniSE [6] studies unified screenshot representations, Unveil [7] distills visual and textual evidence into a parsing-free retriever, and recent systems address iterative visual RAG, long documents, and zero-shot retrieval [8--10]. ViDoRe V3 [3] broadens evaluation to complex professional documents and multilingual queries.

The closest efficiency study is Light-ColPali [5], which investigates query-independent pruning and token merging for index storage. Its results show that irreversible pruning is difficult when future queries are unknown. AdaColRAG instead retains the index and reduces online scoring work after the query is available. The two approaches target different resources and can be combined.

### 2.2 Dense and late-interaction retrieval

Dense passage retrieval [13, 28--30] maps queries and documents to one vector and enables efficient candidate search. Late-interaction models such as ColBERT and ColBERTv2 [11, 12] preserve multiple contextualized vectors and typically improve fine-grained matching at greater scoring cost. AdaColRAG uses this distinction explicitly: dense representations generate candidates, while selected ColPali tokens rerank them.

### 2.3 Efficient vision transformers and token reduction

DynamicViT [24], token reorganization [25], TokenLearner [26], and Token Merging [27] reduce computation inside vision models. These methods generally optimize image inference rather than query-document matching. AdaColRAG does not alter the encoder. It selects stored page tokens according to a retrieval query and measures the resulting effect on ranking, fallback, and candidate operations.

### 2.4 Selective computation and retrieval confidence

Selective prediction invokes an expensive action only when a cheaper prediction is insufficient [19]. Retrieval systems similarly use margins, score distributions, or cross-retriever agreement to assess uncertainty. AdaColRAG combines rank margin, entropy, and query-evidence coverage. The recovery path is fully included in the reported computational accounting.

## 3 Problem Formulation

Let a query be represented by normalized token embeddings

\[
Q=[q_1,\ldots,q_m]\in\mathbb{R}^{m\times d},
\]

and a page by normalized visual embeddings

\[
D=[d_1,\ldots,d_n]\in\mathbb{R}^{n\times d}.
\]

Full late interaction computes

\[
s_{\mathrm{LI}}(Q,D)=\frac{1}{m}\sum_{i=1}^{m}\max_{1\leq j\leq n}q_i^\top d_j.
\]

For corpus size \(N\), exhaustive scoring has work proportional to \(O(Nmnd)\). A two-stage retriever first selects \(C\ll N\) candidates. AdaColRAG then chooses a query-dependent subset \(S_Q(D)\) of size \(K_Q\ll n\):

\[
\tilde{s}_{\mathrm{LI}}(Q,D)=\frac{1}{m}\sum_{i=1}^{m}\max_{j\in S_Q(D)}q_i^\top d_j.
\]

We distinguish two efficiency quantities. **Local token reduction** measures compression only within scored page operations:

\[
R_{\mathrm{local}}=1-\frac{\sum_q T_q}{\sum_q T_q^{\mathrm{full}}}.
\]

**System visual-token work reduction** compares actual scoring work with exhaustive full-token ColPali:

\[
R_{\mathrm{system}}=1-\frac{\mathbb{E}_q[T_q]}{N\bar n},
\]

where \(ar n\) is the mean stored token count per page. The latter combines candidate pruning and token selection and must not be interpreted as index-storage reduction.

## 4 Method

### 4.1 Dense candidate generation

VisRAG-Ret supplies normalized dense vectors \(u_Q\) and \(u_D\). Cosine similarity retrieves the Top-\(C\) candidate pages. Controlled baselines also use a mean-pooled ColPali vector,

\[
\bar q=\operatorname{norm}\left(\frac{1}{m}\sum_iq_i\right),\qquad
\bar d=\operatorname{norm}\left(\frac{1}{n}\sum_jd_j\right),
\]

to isolate candidate-source effects.

### 4.2 Query-complexity budgeting

The controller combines query length, token dispersion, and coarse ambiguity:

\[
f_{\mathrm{len}}=\min(m/m_0,1),
\]

\[
f_{\mathrm{disp}}=\frac{1}{m}\sum_i(1-q_i^\top\bar q),
\]

\[
f_{\mathrm{amb}}=\operatorname{clip}\left(1-\frac{c_1-c_2}{\tau_m},0,1\right),
\]

where \(c_1\geq c_2\) are the two highest coarse scores. The aggregate complexity is

\[
z_Q=\frac{w_lf_{\mathrm{len}}+w_df_{\mathrm{disp}}+w_af_{\mathrm{amb}}}{w_l+w_d+w_a}.
\]

The budget is quantized to a multiple of eight:

\[
K_Q=\operatorname{RoundMultiple}\left(K_{\min}+z_Q(K_{\max}-K_{\min}),8\right),
\]

with \(K_{\min}=32\) and \(K_{\max}=128\).

### 4.3 Query-aware token selection

For page token \(d_j\), query relevance is

\[
r_j=\max_iq_i^\top d_j.
\]

Starting from the most relevant token, selection proceeds greedily:

\[
j^*=\arg\max_{j\notin S}\left[\lambda_rr_j-\lambda_c\max_{k\in S}d_j^\top d_k+\lambda_lg(j,S)\right].
\]

The redundancy term suppresses near-duplicate evidence. The coverage bonus \(g(j,S)\) favors approximate spatial bins that are underrepresented. The implementation updates maximum redundancy incrementally; when \(\lambda_c=\lambda_l=0\), it uses an equivalent Top-\(K\) fast path.

### 4.4 Dense fusion

After min--max normalization over candidates, the main system combines visual late-interaction and dense scores:

\[
s_{\mathrm{fuse}}=(1-\alpha)\hat s_{\mathrm{LI}}+\alpha\hat s_{\mathrm{dense}},
\]

with \(\alpha=0.15\). The OCR extension adds a normalized lexical score and is evaluated separately.

### 4.5 Confidence-aware recovery

Confidence combines top-rank margin, inverse normalized entropy, and query evidence coverage. For the current top page,

\[
c_{\mathrm{cov}}=\frac{1}{m}\sum_i\mathbf{1}\left[\max_{j\in S_Q(D_1)}q_i^\top d_j\geq\tau_s\right].
\]

The final confidence is

\[
c_Q=w_mc_{\mathrm{margin}}+w_ec_{\mathrm{entropy}}+w_vc_{\mathrm{cov}}.
\]

If \(c_Q<\tau_c\), the Top-100 dense candidates are scored with full page tokens. Both the initial compressed pass and recovery pass count toward latency, operations, and token work.

## 5 Experimental Design

### 5.1 Datasets

The submission workflow evaluates four ViDoRe V3 collections [3]: Finance EN, Industrial, Pharmaceuticals, and Finance FR. The first three test domain transfer in English; Finance FR provides a multilingual condition. The exact number of pages, queries, qrels, and dataset checksums are read from generated manifests and reported in the final table.

| Dataset | Domain | Evaluation language | Purpose |
|---|---|---|---|
| ViDoRe V3 Finance EN | annual financial reports | English | primary and archived-pilot continuity |
| ViDoRe V3 Industrial | industrial technical documents | English | layout and terminology transfer |
| ViDoRe V3 Pharmaceuticals | pharmaceutical documents | English | scientific and table-heavy transfer |
| ViDoRe V3 Finance FR | financial reports | French | multilingual robustness |

No retriever is trained on these evaluation queries. Hyperparameter sensitivity must be conducted on a development partition or a held-out dataset; test-set threshold adjustment is not used as primary evidence.

### 5.2 Model provenance and exported representations

The fine retriever is the official merged checkpoint `vidore/colpali-v1.3-merged`. The merged checkpoint is used to eliminate ambiguity caused by adapter-key remapping. The exporter records the model identifier, model class, total parameter count, merged-checkpoint status, and checkpoint verification in `manifest.json`. A submission run fails if the checkpoint is not verified.

The dense retriever is `openbmb/VisRAG-Ret`. ColPali pages and queries are exported as normalized multi-vector representations; VisRAG pages and queries are exported as normalized single vectors. All matrix experiments reuse the same embeddings for a dataset.

Approximate two-dimensional positions are reconstructed from token order on a square grid. They support a coverage heuristic but are not claimed to be exact semantic or encoder patch coordinates.

### 5.3 Seventeen-system controlled matrix

The experiment matrix is organized into five groups.

| Group | Systems | Question answered |
|---|---|---|
| External/exhaustive baselines | VisRAG-Ret; exhaustive ColPali | How strong are single-vector and full multi-vector retrieval? |
| Candidate controls | ColPali-mean Top-50 + full tokens; VisRAG Top-50 + full tokens | How much comes from candidate source and candidate pruning alone? |
| ColPali-mean token baselines | Fixed-32/64/128; adaptive budget/MMR/fallback | What happens without VisRAG candidate generation? |
| Identical-VisRAG-candidate controls | Fixed-112/128; adaptive budget; adaptive MMR; adaptive fallback | What does each token policy contribute on exactly the same Top-50 candidates? |
| Complete systems | AdaColRAG; AdaColRAG + OCR | What is the effect of dense fusion and lexical extension? |

Fixed-112 is included because the archived adaptive controller averaged approximately 114 tokens, making it a closer budget-matched baseline than Fixed-128. The chain

\[
\text{Full tokens}\rightarrow\text{Fixed}\rightarrow\text{Adaptive budget}\rightarrow\text{Adaptive MMR}\rightarrow\text{Fallback}\rightarrow\text{Dense fusion}
\]

uses identical VisRAG candidates wherever possible.

### 5.4 Metrics

Effectiveness metrics are nDCG@5, nDCG@10, Recall@1/5/10, and MRR@10. Efficiency metrics are tokens per scoring operation, local token reduction, visual tokens processed per query, scoring operations per query, system visual-token work reduction, mean latency, p50 latency, and p95 latency. Reliability metrics are confidence, low-confidence rate, fallback rate, and effectiveness on fallback and non-fallback subsets.

### 5.5 Statistical analysis

All systems retain query-level rankings. For primary comparisons, we compute paired query-level nDCG@5 differences and 10,000 paired bootstrap samples. We report the mean difference, 95% interval, two-sided bootstrap probability, and the fraction of queries improved. The primary comparisons are:

1. exhaustive ColPali versus AdaColRAG;
2. VisRAG-Ret versus AdaColRAG;
3. VisRAG Top-50 full tokens versus AdaColRAG;
4. VisRAG Top-50 Fixed-112 versus adaptive budget;
5. adaptive budget versus adaptive MMR;
6. adaptive MMR versus adaptive fallback;
7. adaptive fallback without fusion versus complete AdaColRAG.

### 5.6 Timing protocol

The workflow records CPU, GPU, package versions, Git commit, environment variables, and BLAS thread settings. Retrieval timing is measured over preloaded embeddings and excludes image/query encoding, disk loading, network transfer, and downstream generation. Key systems are run once for warm-up and three measured repetitions by default. The paper reports mean and standard deviation across repetitions. Because the core implementation uses NumPy on CPU, these results characterize retrieval-stage scoring rather than end-to-end serving latency.

### 5.7 Reproducibility and integrity checks

A result bundle is accepted only if:

- every matrix result exists and contains a trace for every query;
- all experiments share one dataset checksum;
- document and query counts match both embedding manifests;
- dense embeddings are attached only to declared experiments;
- ColPali uses a verified merged checkpoint;
- all reported metric and efficiency values are finite;
- hardware, threading, model identifiers, and Git commit are preserved.

Local token reduction was 47.25%, while full-corpus visual-token work reduction was 98.31%. These values must not replace the merged-checkpoint submission rerun.

## 7 Discussion

AdaColRAG should be interpreted as an online scoring policy rather than an index compressor. It retains all ColPali vectors and therefore does not reduce storage. Its potential value is selective computation: easy queries remain on a compressed candidate route, while difficult queries receive additional evidence.

The controlled matrix is essential for causal interpretation. If VisRAG Top-50 full-token scoring already matches the complete method, the main contribution is candidate generation rather than token selection. If adaptive MMR improves over Fixed-112 and adaptive relevance-only at comparable token use, the selector has independent value. If fallback improves effectiveness but consumes most of the saved work, calibration rather than compression becomes the main research problem.

Dense-only VisRAG is a strong and efficient baseline. AdaColRAG need not dominate it on every metric to be useful, but any claim of superiority must specify the target: early-rank graded relevance, fine-grained evidence selection, reliability under uncertainty, or downstream answer quality.

## 8 Limitations and Threats to Validity

First, approximate token positions support only a coarse coverage heuristic. Second, the current method is training free and may leave quality gains available to learned budgeting or calibration. Third, retrieval-stage CPU timing excludes encoder and I/O costs and is not a production serving benchmark. Fourth, full-token fallback can dominate computation when confidence is poorly calibrated. Fifth, the full ColPali index remains stored. Sixth, test-set operating-point adjustment would invalidate generalization claims; threshold sensitivity must use development data. Seventh, multilingual robustness is evaluated only through Finance FR. Eighth, paired bootstrap intervals characterize query sampling uncertainty but not model-training uncertainty because the encoders are frozen. Finally, downstream generation is outside the principal evaluation, so retrieval gains do not automatically imply answer-quality gains.

## 9 Ethical Considerations

The datasets contain publicly released professional documents and benchmark queries. The system does not generate financial or medical advice. Retrieval errors can omit qualifying disclosures or surface misleading pages; downstream systems should preserve provenance and provide access to original documents. Private deployments may expose sensitive queries through traces and logs, requiring access controls and retention limits. Dataset and model licenses, including the Gemma-derived ColPali checkpoint license, must be respected. Efficiency claims should identify the hardware, software, and accounting boundary under which they were measured.

## 10 Conclusion

AdaColRAG reframes visual-token reduction as query-conditioned selective computation. Dense candidate generation limits the page set, adaptive selection retains relevant and nonredundant evidence, and confidence-aware recovery protects uncertain queries. The archived Finance EN pilot suggests a promising quality--cost operating point, but the submission claim rests on the new merged-checkpoint, identical-candidate, multi-domain, statistically analyzed rerun. The revised framework produces all 17 controlled systems, integrity reports, repeated timing, cross-domain tables, and manuscript-ready Markdown through one command.
